# GitHub Pages Hub Site Guide

The manual for building **and keeping** a personal hub site on GitHub Pages — the Asdale way: one repo, one `index.html` routing readers to books, guides, and tools, project cards and breadcrumbs, error pages people can escape, redirects when slugs change, release-note columns, and a tidy ninety-minute monthly maintenance ritual.

This repository contains both the **manual** (plain-Markdown chapters in `manual/`) and a **small working example site** generated by a Python standard-library build script, tested by `check.py`. It is deliberately distinct from its siblings: `github-for-everyone-handbook` covers GitHub fundamentals, and `author-site-starter-template` is starter code — this one teaches the *pattern* and the *upkeep*.

## What the example site demonstrates

- **One index** routing to `/books/`, `/guides/`, `/tools/`
- **Project cards** (tag + title + blurb, whole card is a link)
- **Breadcrumbs and skip links** on every full page
- **A 404 people can escape** (three working doors)
- **Redirects when slugs change** (`/tools/prompt-saver/` → `/tools/prompt-vault/`, via `meta refresh` + `location.replace`)
- **Release-note columns** (Added / Changed / Fixed, dated, newest first)
- **The maintenance ritual** rendered as its own page (`/maintenance/`)

## Run it

```bash
python3 build.py      # builds the example site into site/
python3 check.py      # runs the tests: prints PASS or FAIL + reasons
python3 -m http.server -d site 8000   # optional local preview
python3 backup.py     # optional: make a tidy dated backup
```

Requires only Python 3.10+ and nothing else. To publish on GitHub Pages, upload the built `site/` contents to your pages repository with `404.html` at the root. (One preview caveat: Python's built-in `http.server` shows its own generic 404; GitHub Pages serves your `404.html`.)

## Tests

`check.py` validates every generated page: internal links resolve, each page carries a breadcrumb, an escape hatch to home, and a `main` landmark; the 404 has all three escape routes; redirect stubs point directly at their final destination; release notes carry all three column headings; no secrets are embedded. `python3 check.py` exits 0 on `PASS`.
